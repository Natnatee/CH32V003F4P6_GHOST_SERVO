# เครื่องส่ง AM312 → IR LED 38kHz

## โค้ดปัจจุบัน: IR (แทน RF)
- PC4 **ขาชิป 14** → วงจรขับ IR LED แบบ Active HIGH; HIGH ทำให้ LED ส่อง ต้องมีตัวต้านทานจำกัดกระแส/วงจรขับที่เหมาะสม ห้ามต่อ IR LED เปล่าตรง GPIO
- ส่งพาหะประมาณ 38kHz duty 33% ด้วย SysTick absolute deadlines; receiver ต้องเป็นชนิด demodulated 38kHz OUT Active LOW ไม่ใช่ photodiode เปล่าหรือโมดูลตรวจสิ่งกีดขวาง
- PIR OUT → PC1 ขาชิป11, LED แสดงผล → PC2 ขาชิป12 เหมือนเดิม
- PIR HIGH ส่งรหัส A5C33C ซ้ำ เว้น 30ms; LED ติด3s/ดับพัก3s โดยไม่หยุดการส่งตาม PIR
- จ่ายไฟ/ระดับลอจิกตามสเปกโมดูลจริง ไม่ต่อไฟ12V เข้าชิปหรือ LED ตรง ๆ ไม่ต่อไฟโปรแกรมเมอร์ซ้อน

แฟลชใช้งานจริงจากโฟลเดอร์หลัก:
```bash
pio run -d transmitter -e ch32v003f4p6 -t upload
```

ทดสอบ IR โดยไม่รอ PIR (ส่ง8แพ็กเก็ต พัก1s LEDติดขณะส่ง):
```bash
pio run -d transmitter -e ir_test -t upload
```
ต้องอัปโหลดเฟิร์มแวร์ IR ทั้งสองฝั่ง เปลี่ยนชื่อ environment จาก rf_test เป็น ir_test แล้ว ไม่มีโหมด RF ปัจจุบัน ทดสอบพาหะ/ระยะบนฮาร์ดแวร์จริงอีกครั้ง

ผังขาชิปด้านล่างยังใช้อ้างตำแหน่ง PC4/PC1/PC2 ได้ แต่ข้อความ RF และคำสั่ง rf_test ด้านล่างเป็นประวัติเก่า ไม่ใช่การใช้งานปัจจุบัน

---
## ประวัติการทดสอบ RF ก่อนเปลี่ยนเป็น IR

โปรเจกต์ PlatformIO แยกสำหรับ CH32V003F4P6 ใช้ clock 48 MHz + PLL ตามโปรเจกต์หลัก ไม่มี printf และไม่แก้ไข PD1 (SWIO สำหรับโปรแกรม/ดีบั๊ก)

## โหมดทดสอบ RF ล้วน (`rf_test`)
รันจากโฟลเดอร์หลัก:
```bash
pio run -d transmitter -e rf_test -t upload
```
ไม่อ่าน PIR ส่ง A5C33C ด้วย timing เดิมชุดละ 8 แพ็กเก็ต (~0.39s) แล้วเงียบ 1s; LED PC2 ติดขณะส่งทั้งชุด ไม่ใช่สถานะ PIR ในโหมดนี้ ต้องแฟลชฝั่งรับด้วย `pio run -d receiver -e rf_test -t upload` และดู log ที่ตัวรับ

กลับโหมด PIR เดิม:
```bash
pio run -d transmitter -e ch32v003f4p6 -t upload
```
ค่าปริยายยังเป็นโหมดเดิม ไม่ต้องแก้สาย PIR โหมดทดสอบไม่อ่านมัน แยกไฟและ GND ข้ามฝั่งตามเดิม คู่มือการอ่าน log อยู่ `../receiver/README.md`

## ไฟแสดง PIR
PC2 (ขาชิป TSSOP20 หมายเลข 12) Output Push-Pull Active High → R 330Ω → LED ขั้วบวก; LED ขั้วลบ → GND
PIR HIGH เริ่ม LED ติด 3s แม้ PIR กลับ LOW จากนั้นดับพัก 3s ไม่รับ trigger LED ซ้ำระหว่างรอบ เมื่อพักครบถ้า PIR ยัง HIGH เริ่มใหม่ได้ RF ยังส่งตาม PIR HIGH เหมือนเดิม ไม่หยุดเพราะ LED พัก ใช้ SysTick จับเวลา LED (คลาดเคลื่อนได้ประมาณหนึ่งแพ็กเก็ตและช่วงพัก รวมราว 80ms) โหมด rf_test ยังแสดง LED ตามชุดส่งเดิมฝั่

```text
CH32V003F4P6 TSSOP20 มองด้านบน
           +---U---+
 PD4     1 |       | 20 PD3
 PD5     2 |       | 19 PD2
 PD6     3 |       | 18 PD1 --> SDI
 PD7     4 |       | 17 PC7
 PA1     5 |       | 16 PC6
 PA2     6 |       | 15 PC5
 GND     7 |       | 14 PC4 --> RF TX DATA
 PD0     8 |       | 13 PC3
 VDD     9 |       | 12 PC2 --> R 330Ω --> LED --> GND
 PC0    10 |       | 11 PC1 <-- AM312 OUT
           +-------+
```
ผังขาชิป ไม่ใช่ตำแหน่ง header บอร์ดขยาย

## จุดที่ยืนยันจากการทดสอบจริง
DATA ตัวส่งต้องต่อ **PC4 = ขาชิป TSSOP20 หมายเลข 14** ไม่ใช่ขา 10 (PC0) หลังย้ายสาย ผู้ใช้ยืนยันรับ A5C33C และ match เพิ่มต่อเนื่องแล้ว

## ต่อสาย
- AM312 OUT → PC1 (floating input ไม่มี pull-up/pull-down ภายใน)
- RF433 ASK TX DATA → PC4 (push-pull, LOW ขณะว่าง)
- ต่อ GND ของ MCU, AM312 และ RF TX ร่วมกัน
- จ่ายไฟ AM312 ตามข้อกำหนดของโมดูลจริง และตรวจแรงดัน OUT ให้เหมาะกับ MCU; อย่าปล่อย PC1 ลอยเมื่อใช้งาน
- ใช้โมดูลส่ง ASK ย่าน **433 MHz**; เฟิร์มแวร์สร้างสัญญาณ DATA ไม่ได้กำหนดความถี่ RF
- **ไฟเลี้ยง RF TX:** ใช้ 3.3V เฉพาะเมื่อโมดูลรองรับ หากต้องจ่าย 5V ให้ตรวจสอบก่อนว่า DATA รับลอจิก 3.3V ได้ มิฉะนั้นต้องใช้วงจรแปลงระดับที่เหมาะสม ไม่รับรองความเข้ากันได้ของฮาร์ดแวร์โดยไม่ตรวจสเปก

## การทำงาน
PIR HIGH ส่งซ้ำตลอด โดยเว้น 30 ms ระหว่างแพ็กเก็ต ไม่มี application cooldown เมื่อ LOW ไม่เริ่มแพ็กเก็ตใหม่ (แพ็กเก็ตที่เริ่มแล้วส่งจนจบ)

- Sync: HIGH 300 µs / LOW 9300 µs
- ข้อมูล 24 บิต MSB first: `0xA5C33C`
- บิต 0: HIGH 300 µs / LOW 900 µs
- บิต 1: HIGH 900 µs / LOW 300 µs
- End: HIGH 300 µs / LOW 9300 µs

## Build เท่านั้น
รันจากโฟลเดอร์ราก `CH32V003F4P6_CHECK`:

```sh
pio run -d transmitter
```

ไม่ได้สั่ง upload; ค่า upload protocol คือ `minichlink`
